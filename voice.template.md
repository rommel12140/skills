# Voice

Copy this file to the root of a project as `voice.md`.
Both `copy-review` and `design-review` read it before their own catalogs and treat it as authoritative.

Leave a section empty rather than filling it with something plausible.
An empty section means the skill falls back to its global catalog.
A wrong section means the skill enforces the wrong thing.

## Who this is for

The actual reader, named concretely.
Their job, what they already know, and what they are trying to get done when they land here.

Not "businesses looking to grow".

## What we sell them

The product in one sentence, with no adjectives.

## Numbers we are allowed to state

Every figure the copy may cite, each with its source.

| Figure | Source | Last checked |
| :--- | :--- | :--- |
|  |  |  |

Any number appearing in copy that is not on this list is a finding.
This is the mechanism that catches invented statistics, so an incomplete list produces false findings and an over-generous list produces none.

## Words this project uses

Domain nouns the reader already knows.
The skills will prefer these over generic substitutes.

## Words this project does not use

Project-specific bans, on top of the global catalog.
Competitor names, deprecated product names, terms the audience reads as jargon.

## Visual language

What is the equivalent mark in this industry?
What does the rest of the site already use?

This section is what `design-review` checks gate `X1` against.
Without it, `X1` cannot run and the skill will say so.

## Tone notes

Anything the catalogs would otherwise get wrong.
For example: a project whose audience genuinely expects formal register, or one where a normally banned word is the correct domain term.
