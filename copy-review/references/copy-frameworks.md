# What to write

The catalog in `copy-tells.md` only removes.
This file covers what goes in the space.

Adapted from Apache-2.0 material in `boraoztunc/skills`.
See `ATTRIBUTION.md`.

## The order of operations

Most weak copy is weak because it was written before the writer knew what they were claiming.

1. **Who** is reading, and what are they trying to get done.
2. **What changes** for them, stated as a difference between before and after.
3. **Why it is true**, which is the number, the mechanism, or the demonstration.
4. **What they do next**, in one action.

Write those four as bare sentences first.
Then make them read well.
Doing it in the other order produces prose that sounds finished and says nothing, which is the failure `VO1` catches.

## The promise

A promise names the change and the person it happens to.

Weak: "Powerful analytics for modern teams."
Working: "See which of your queries cost the most, in the first five minutes."

The test: can the reader picture the moment it happens?
If not, the promise is a category, not a promise.

## Headlines

Three shapes that hold up, in rough order of usefulness:

| Shape | When it works | Example form |
| :--- | :--- | :--- |
| The specific outcome | There is a real number or a real before and after | "40 minutes of tests, finished in 11" |
| The named problem | The reader already feels it and has no name for it | "Your staging data is six weeks old" |
| The plain description | The product is unfamiliar and needs explaining before selling | "A read-only mirror of production, refreshed nightly" |

Avoid the shape that pairs an abstraction with a benefit ("Streamline your workflow and ship faster").
It fits any product, which is why it is easy to write and why it does nothing.

## Plain-English substitutions

| Instead of | Write |
| :--- | :--- |
| utilize | use |
| leverage (verb) | use |
| facilitate | help, or name the action |
| in order to | to |
| at this point in time | now |
| prior to | before |
| subsequent to | after |
| a number of | the number |
| has the ability to | can |
| is able to | can |
| provides the capability for | lets you |
| in the event that | if |
| due to the fact that | because |
| for the purpose of | to |
| it is important to note that | delete, then state the thing |
| on a daily basis | daily |
| a wide range of | the range, or the count |

The pattern: the left column names a category of action, the right column names the action.

## Transitions

`ST1` and `O4` usually appear together.
The cause is the same: sentences placed side by side with no relationship, then joined with a connective that claims one.

Three transitions that carry actual weight:

- **Cause**: "which is why", "so", "because". Use when the second sentence follows from the first.
- **Contrast**: "but", "except", "the exception is". Use when the second sentence limits the first.
- **Escalation**: "worse", "and it compounds", "the same is true of". Use when the second sentence raises the stakes.

If none of the three fits, the sentences are not related and one of them belongs elsewhere.
Deleting the connective and leaving the sentences adjacent is almost always better than reaching for "Moreover".

## Rhythm

Vary sentence length because the meaning wants it varied.

A long sentence carries a chain of reasoning, holding several clauses in tension until it resolves at the end.
A short one lands.

The reliable test is reading aloud.
Where you run out of breath, cut.
Where three sentences in a row hit the same beat, one of them is padding.

## The last pass

Two questions, applied to the finished piece:

1. Which sentence would survive on a competitor's site?
   Rewrite or delete each one.
2. What did the reader learn that they could not have guessed?
   If the answer is nothing, the piece is not finished regardless of how it reads.
