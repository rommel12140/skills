# Case 09 - expected output

These are example assemblies, not real session or business details.
Use the existing voice, date, format and evidence rules for both scenarios.

## Busy day reference

```
EOD for today 8/20/26

Report workflows. That's where most of the day went. Pretty happy, we can finally send the right report to each client. Monthly report is still missing the late payments, not done, gonna finish that tomorrow.

 - Report workflows. Fixed who gets which report. The report sheet is done. Monthly report is still missing the late payments, not done, gonna finish that tomorrow.
 - Booking forms, fixed the confirmation that was sending people to the wrong day. Bookings were being missed, tested it with two bookings, all good now.
 - Task management, put owners and due dates on the overdue client jobs. The team can see what's waiting on them now. Done.
 - Client handoff, sent the welcome pack and access instructions. They're waiting on us for the training date, still need to arrange that tomorrow.
```

Outside the report:

```
Order: report workflows first since that's where most of the day went, then booking forms, task management and client handoff. Left out the small logo spacing fix. Say the word if you want it shuffled.
```

### Busy day checks

- [ ] Four substantive workstreams survive: report workflows, task management, booking forms and client handoff.
- [ ] Report workflows is first and opens the main outcome.
- [ ] Report routing, the report sheet and the unfinished monthly report are grouped together, rather than consuming separate priority slots.
- [ ] The small logo fix does not earn a standalone bullet or displace one of the four substantive workstreams.
- [ ] Mentioning the logo first and last, its live status and its repeated checks do not promote it.
- [ ] Monthly report stays unfinished, with late payments and tomorrow preserved.
- [ ] The welcome pack is sent, but arranging the training date remains unfinished.
- [ ] Task ownership and due dates survive; they are substantive work, not routine planning.
- [ ] Booking forms and task management may swap order; both stay ahead of client handoff.
- [ ] Every claim traces to the notes, including the count of two bookings.

## Design-focused day reference

```
EOD for today 8/21/26

Northbank identity is the main priority today, the client needs the new logo for Monday's launch. Spent most of the day on it.

 - Northbank identity. Logo is done, the shapes and spacing are where we wanted. Sent it to the client, waiting on sign-off. The brand sheet is started, still need the small-size version tomorrow.
```

Outside the report:

```
Order: Northbank identity first since that's the main priority for Monday's launch. Left out the small report heading fix and the unchanged booking check. Say the word if you want it shuffled.
```

### Design-focused day checks

- [ ] Northbank identity opens the main outcome and earns the first bullet.
- [ ] The logo is included because of the stated priority, launch consequence and substantial effort.
- [ ] The logo is done and sent, not approved or already live.
- [ ] Waiting on sign-off and the unfinished brand sheet stay in the same workstream.
- [ ] The small report heading fix does not earn a standalone priority merely because report workflows mattered on the previous day.
- [ ] Yesterday's booking repair does not become new progress today; the unchanged check earns no bullet.
- [ ] One substantive priority produces one bullet, without padding.

For both days, preserve intelligible wording and the plain owner voice.
Use one main-outcome paragraph, ` - ` bullet markers and no characters above U+007F.
A blanket ban on logos fails the design-focused scenario.
