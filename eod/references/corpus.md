# The corpus

Three EODs, all written by the owner, on consecutive working days.
Together they are the authority on format, tone, length and punctuation.

Do not edit any of them to make a rule tidier.
If a rule does not survive contact with a specimen, the rule is wrong.

## How to read a corpus rather than a sample

The first version of this skill was built on 30 July alone, and several of its rules turned out to be facts about that one day rather than facts about him.

So the working method is now:

1. A rule needs support from more than one specimen before it is stated as a requirement.
2. A rule supported by one specimen and contradicted by another is not an inconsistency in him. It is a bug in the rule, and it becomes an explicit "varies, do not normalise" rule.
3. Where the three differ, reproduce whatever he used that day. Never pick a canonical form.

`voice-rules.md` cites the supporting specimens for every rule, so this is checkable rather than a promise.

### One uncertain boundary

In his message the words `Hey! Good day,` sit at the end of the 29 July block and immediately before `EOD for today 7/28/26:`.

Reading them as the greeting that opens the 28 July report is the natural reading, and it is the one taken above, but it is an inference rather than something he stated.

No rule in `voice-rules.md` depends on which report those words belong to.
Everything else in both specimens is certain.

## What holds across all three

Short list, and it is short on purpose.

| Thing | Support |
| :--- | :--- |
| The date is `M/D/YY`, unpadded, two-digit year | A, B, C |
| The words `EOD for today` appear | A, B, C |

## Specimen A: 30 July 2026

### Measurements

| Thing | In the specimen |
| :--- | :--- |
| Greeting | none |
| Date line | `EOD for today 7/30/26`, then a blank line |
| Main outcome | One paragraph, 6 sentences, 55 words |
| Bullets | 4 |
| Longest bullet | 7 sentences, 52 words (Moving Scrubs) |
| Shortest bullet | 1 sentence (kitchen mockup) |
| Separator after the workstream name | full stop in 2 bullets, colon in 1, none in 1 |

### The main outcome

It is not a summary of the bullets.

Read the order: it names the centre of gravity (`ProfitsX development`), then how it felt (`Exciting, everything's coming together`), then what was actually worked (`Focused on Homepage today`), then the second thread (`MovingScrubs, wired up the resources automation from GHL`), then an honest note on pace (`A little slower today with less AI help`), and it closes on tomorrow.

The parenthetical `(noting all the things we've talked about yesterday)` is a side note kept inside the sentence rather than promoted to its own line.
Parentheses are in the voice. Dashes are not.

### The bullets

The separator after the name varies inside this one report: `ProfitsX Homepage.` uses a full stop, `Moving Scrubs:` uses a colon, and the fourth bullet has no name at all and starts with the verb, `Prepared the info and brand settings for the kitchen mockup`.

Bullet 1 states unfinished work as unfinished and names what unblocks it: `Not yet done but tomorrow, we'll be able to import it to webflow`.
It then gives the reason the thing mattered: `Homepage is being focused right now because once this is done, the other pages will be easier since we now have the full concept`.

Bullet 2 runs short declaratives back to back: `Webinars are done. GHL Login is done. Resources is done.`
Collapsing that into `Webinars, GHL login and resources are done` loses the sound of clearing a list.

## Specimen B: 29 July 2026

### Measurements

| Thing | In the specimen |
| :--- | :--- |
| Greeting | `Hey!`, folded into the date line |
| Date line | `Hey! EOD for today: 7/29/26`, no blank line after it |
| Main outcome | One paragraph, 3 sentences, 46 words |
| Bullets | 4 |
| Longest bullet | 6 sentences (the wireframe bullet) |
| Separator after the workstream name | none in all four |

### What this specimen adds

**The greeting can ride on the date line.** `Hey! EOD for today: 7/29/26`, with the colon after `today` rather than after the date.

**The main outcome can be almost all plan and shortfall.** `Was hoping to be done today but it's too ambitious, tomorrow I'll try so that I can move on to the tools, resources, leadgen, CMS, and other that needs to be wired.`
One sentence carries the miss, the retry and the queue behind it.

**A URL goes inline and unlabelled, followed by why it is there.**

`ProfitsX wireframe done earlier this morning. https://profitsx-10c54d.webflow.io/app/wireframes/visual Gonna put it here for documentation.`

No link text, no parentheses, no "see:". The bare URL sits in the sentence flow and the next sentence says what it is for.

**He addresses the reader and defends time spent.** `Don't worry, this didn't take me long to create.`

That sentence is doing real work: the wireframe could read as a detour, so he pre-empts the challenge. This is a move the skill has to be able to carry. It is not an aside to be trimmed.

**Playful constructions are voice.** `Animations animations++ .` with the space before the period. `wireframe + start of implementation!`. `+` as a mid-sentence connector in `a little touch of finish + Little some help to Ron`.

**Named colleagues appear as he writes them.** `Little some help to Ron regarding adding a button on his checklist.`

**Bullets need not name a workstream.** All four here run the name into the sentence or skip it: `Started implementation of home, service page, faq, and philosophy page.`, `Moving scrubs was more finished than I thought`.

**The non-standard grammar is dense.** `it is hard to implement and fix 3D animations in webflow than just html`. `and other that needs to be wired`. `Little some help to Ron`. `Moving scrubs was more finished than I thought`.

None of those are errors to repair. See `voice-rules.md`, `W1`.

## Specimen C: 28 July 2026

### Measurements

| Thing | In the specimen |
| :--- | :--- |
| Greeting | `Hey! Good day,` on its own line, then a blank line |
| Date line | `EOD for today 7/28/26:`, trailing colon, no blank line after it |
| Main outcome | One paragraph, 3 sentences, opening with a leading space |
| Bullets | 3, with no blank line between the main outcome and the first |
| Separator after the workstream name | none in 1, hyphen in 2 |

### What this specimen adds

**Three bullets.** This is the proof that four is a ceiling and never a target.

**The hyphen separator.** `Created Mockups - R&J for GHL and Reico for Webflow.` and `Templates - Checked all around the templates`.
With this specimen the attested set is full stop, colon, hyphen, and none.

**His whitespace is his.** The main outcome opens with a leading space, and the third bullet has a double space mid-sentence: `which is already planned out.  Added animations and inspirations for profitsx.`
Neither is tidied.

**Project-name capitalisation varies inside one report.** `Profitsx` in the main outcome twice, `ProfitsX` in bullet 1, `profitsx` in bullet 3. Three spellings, one report, all correct.

**Client codes and what the client is.** `one for GHL (R&J) and one for Construction Company (Reico)`. The code and the description travel together, in his parentheses.

**No tomorrow line and no feeling.** This report just ends on `how animation will go along.`
Any rule that requires a forward-looking close or a stated feeling is contradicted here.

**More non-standard grammar to preserve.** `gonna start forming basic wireframe which is already planned out`. `On which pages are static, which pages are story telling with animations.`

## Register, across all three

First person. `we` for the work, `I` for himself.
Contractions throughout: `everything's`, `we'll`, `I'm gonna`, `didn't`, `it's`.
`gonna` and `kinda` are in the voice.
Emphasis by capital letters, sparingly: `ALL my AI colleagues`.
Trailing hand waves are in the voice: `and stuff`, `etc.`.
Exclamation marks are in the voice: `works great!`, `implementation!`, `Hey!`.

This is dictated speech.
It is not written prose, it must not be raised into written prose, and the places where it departs from standard English are the voice rather than errors to repair.

`Piecing up together`. `Conceptualize for a better growth engine`. `Little some help to Ron`. `and other that needs to be wired`. `Animations animations++ .`

None of those are mistakes. See `voice-rules.md`, `W1`.
